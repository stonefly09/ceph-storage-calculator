Ceph Storage Calculator

This Ceph storage calculator estimates how much data can be safely stored in a replicated Ceph cluster while still tolerating the failure of the largest node. It is useful for environments where Ceph is deployed as S3 compatible storage for backup, analytics, or application workloads.

Unlike simple “raw capacity ÷ replication factor” calculations, this calculator models a worst-case recovery scenario. It assumes that if the largest node fails, the remaining nodes must have enough free space to fully re-replicate its data without running out of capacity during recovery.

The goal of this calculator is capacity safety, not maximum efficiency. The results are intentionally conservative and are designed to help with planning, not promises.

What This Ceph Storage Calculator Does

It estimates safe usable storage capacity for a Ceph cluster under strict assumptions.

Specifically, it answers the question:

How much data can I store while still guaranteeing that my cluster can recover from the failure of the largest node without hitting a full condition?

The calculator models:

  • A single node failure
  • Loss of the largest node in the cluster
  • Replicated pools (not erasure coding)
  • Full re-replication after failure
  • No additional failures during recovery

If these conditions can be satisfied, the reported capacity is considered “safe” from a storage-space perspective.

Assumptions Behind the Ceph Calculator

Replication Model

  • Only replicated pools are modeled
  • The pool replication size defines how many copies exist
  • Replicas are assumed to be placed on different nodes
  • Proper CRUSH failure-domain configuration is assumed

Erasure-coded pools are not included due to their different recovery and space behavior.

Failure Scenario Modeled

  • Exactly one node fails
  • The largest node fails
  • No disks or nodes fail during recovery
  • Recovery must complete successfully

Capacity Safety Model

  • Remaining nodes must have enough free space to absorb all missing replicas
  • Re-replication must complete without hitting full or backfill-blocked states
  • Temporary degraded operation may or may not be allowed

This models space safety only, not performance or recovery speed.

Settings Explained

Accept Degraded PGs

When enabled, the calculator allows placement groups to enter a degraded state after a failure.

  • Assumes temporary reduced redundancy
  • Full replication may be restored later

When disabled, enough free space must exist to immediately restore full replication.

Define Each Node Manually

Allows specifying raw capacity per node individually for uneven or unbalanced clusters.

Capacity per Node

  • Total raw storage capacity per node
  • All OSDs are usable
  • CRUSH weights proportional to disk size
  • No distinction between drive types

Total Node Count

Determines replica distribution and recovery feasibility. Small node counts significantly reduce safe capacity.

Number of Replicas

  • Size = 1 → no redundancy
  • Size = 2 → limited fault tolerance
  • Size = 3 → common production default

Understanding Results

Raw Storage

Raw Storage = Capacity per Node × Total Node Count

Safe Storage Size

Maximum amount of data that can be stored while still allowing the cluster to recover from the modeled node failure.

Safe Storage Efficiency

Safe storage expressed as a percentage of raw storage.

OSD Nearfull Ratio

Estimated maximum OSD utilization that still allows full re-replication.

Why Larger Nodes Reduce Safe Ceph Storage Efficiency

  • Increases raw cluster capacity
  • Increases the amount of data lost when a node fails
  • Requires more free space for re-replication

Limitations

  • Multiple simultaneous failures
  • Recovery throttling
  • Uneven OSD utilization
  • Device classes or WAL/DB separation
  • Network bandwidth or latency
  • Recovery time estimation
  • min_size behavior
  • Monitor quorum or availability

FAQs

How much usable storage does Ceph provide?

Usable storage depends on replication, node count, and recovery headroom.

Why is usable Ceph storage lower than raw capacity?

Replication overhead and reserved recovery space reduce usable capacity.

What happens when a Ceph node fails?

Ceph re-replicates missing objects if sufficient free space exists.

What is a safe OSD utilization level?

There is no universal value; this calculator estimates a conservative safe level.
